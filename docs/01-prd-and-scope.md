# 01 — 产品需求与严格边界（PRD & Scope）

## 1. 立项背景与解决的核心问题

通过对比原版 `GeekDesk`（WPF/.NET Framework）与 `GeekDeskNext`（WPF/.NET 8）的实际运行表现，得出关键结论：

1. **WPF + GPU/D3D11 + CLR 常驻内存过高**：桌面启动器在后台运行却长期占用 110MB~330MB 内存，驱动纹理与视觉树开销远超实际业务所需。
2. **托管框架动画与渲染偶发异常**：如 `ScaleTransform` 冻结对象修改异常、透明窗口跨 DPI 坐标偏移、Win32 Backdrop 与 WPF 画刷透明度互相抵消等。
3. **功能冗余稀释核心体验**：外挂 Everything 全盘搜索、旧版二进制（`BinaryFormatter`）迁移逻辑、待办/密码锁/秒表等非核心模块增加了代码复杂度、权限敏感度与维护成本。

因此，**GeekDeskCpp** 的唯一使命是：**只做一件事，并做到极致——轻量、毫秒响应、多年稳定运行的数据可控桌面启动器。**

### 2.2 坚决不做清单（Explicit Non-Goals）

以下功能在架构上**永久禁止引入**，任何 Phase 均不得回退：

- ❌ **禁止 Everything 搜索**：不打包 `Everything.exe`，不加载 `Everything64.dll`，不连任何 Everything 服务，不扫描全盘未知文件。
- ❌ **禁止 GeekDesk 2.x 旧二进制迁移**：不支持旧版 `.Data` / `BinaryFormatter` / NRBF 读取；仅兼容 `GeekDeskNext` 的 JSON Schema v1。
- ❌ **禁止非启动器副业功能**：不做 ToDo 待办提醒、不做分组密码锁、不做桌面秒表（SecondsWindow）、不做屏幕取色器、不做插件商店或脚本引擎。
- ❌ **禁止任何联网行为**：不检查更新、不上传遥测、无在线壁纸/账号同步。

## 3. 性能与资源硬性指标（Budgets）

| 指标 | GeekDesk / Next 参考基线 | GeekDeskCpp 验收目标 |
| :--- | :--- | :--- |
| 安装包/可执行体积 | 数十 MB（含 .NET 运行时/依赖库） | **单文件 < 5 MB**，零外部 DLL |
| 冷启动耗时（至窗口就绪） | 800 ms ~ 2000 ms | **< 150 ms** |
| 热键/中键呼出延迟 | 50 ms ~ 150 ms | **< 16 ms（1 帧内）** |
| 常驻工作集内存（空闲态） | 110 MB ~ 330 MB | **< 20 MB**（不初始化 D3D11/DXGI） |
| 后台静默 CPU 占用 | 0% ~ 1%（偶发 GC） | **0.0%**（纯消息阻塞 + 无后台轮询） |
| 配置文件安全性 | 偶发写半截风险 | **100% 原子替换 + 每日快照 + 回滚保障** |
